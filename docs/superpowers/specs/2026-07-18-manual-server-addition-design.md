# RDGDesk 手动添加服务器设计

日期：2026-07-18  
状态：已与用户确认，待实施

## 目标

让用户无需先导入 `.rdg` 文件，也能在 RDGDesk 中手动添加远程桌面服务器；已有资源库时，也能把服务器加入根分组或指定子分组。手动服务器应复用现有的搜索、分组、属性、凭据继承、删除和连接能力，并在应用重启以及重新导入同一 `.rdg` 后继续保留。

## 已确认的产品行为

### 入口和操作流程

- 侧边栏顶部的 `+` 按钮改为菜单：
  - `添加服务器…`
  - `导入 .rdg…`
- 没有资源库时，从顶部添加服务器会自动创建本地资源库“我的服务器”。
- 已有资源库时，从顶部添加服务器会加入根分组。
- 分组右键菜单增加 `添加服务器…`，服务器直接加入该分组。
- 添加窗口包含：
  - 名称；初始值可随用户输入的地址自动填写，用户仍可修改。
  - IP 地址或域名。
  - 端口；默认值为 `3389`。
- 保存成功后自动选中新服务器，用户可以双击连接。
- 服务器默认继承现有全局凭据，不在添加窗口重复要求账号或密码。

### 保存与数据安全

- 手动服务器使用独立 UUID，保存在 RDGDesk 本地配置中，重启后继续存在。
- 手动服务器不带 `.rdg` 来源指纹；重新导入同一个 `.rdg` 时，现有合并逻辑保留这些本机项目。
- 原始 `.rdg` 文件保持只读，添加、编辑和删除均不改写源文件。
- 密码不写入资源库快照。连接时继续通过现有凭据解析顺序继承全局凭据，并由 macOS 钥匙串保存密码。
- 手动服务器继续支持现有的属性编辑、凭据覆盖、移动、删除、搜索和连接操作。
- 导入另一个不同来源的 `.rdg` 时，如果当前资源库含手动项目，应用必须先明确提示替换影响，不能静默丢失本地项目。

## 数据模型和核心接口

### 手动服务器身份

新增服务器快照具备以下特征：

- `id`：新生成的 UUID 字符串。
- `sourceFingerprint`：`nil`，用于区分本机创建项与 `.rdg` 来源项。
- `displayName`：校验并去除首尾空格后的名称。
- `address`：使用现有序列化规则；IPv4/域名保存为 `host:port`，IPv6 保存为 `[host]:port`。

核心编辑器新增创建操作。操作接收资源库快照、目标分组 ID 和服务器草稿，原子返回更新后的快照及新服务器 ID。目标分组不存在或输入无效时不产生任何快照修改。

### 无资源库时的引导创建

模型层提供一次原子配置更新：

1. 校验服务器草稿。
2. 如果配置没有资源库，创建本地快照，名称和根分组均为“我的服务器”，并使用稳定的本地资源库标识。
3. 将服务器加入根分组。
4. 一次性提交配置。
5. 发布新资源库并选中新服务器。

任何一步失败都不应留下空资源库、半条服务器记录或错误的当前选择。

### 已有资源库时的创建

- 顶部入口把当前资源库根分组 ID 作为目标。
- 分组右键入口把对应分组 ID 作为目标。
- 保存使用现有配置仓库的并发保护；如果窗口打开后资源库已被替换，保存应失败并显示安全、明确的提示，不能写入错误资源库。

## 输入校验

- 名称去除首尾空白后不能为空。
- 地址去除首尾空白后不能为空，且不接受 URL、路径、用户信息或内嵌端口。
- 支持：
  - 合法 IPv4 地址。
  - 不带方括号的合法 IPv6 地址。
  - 符合 DNS 标签规则的域名或主机名。
- 端口必须为整数 `1...65535`，默认 `3389`。
- 错误提示定位到具体问题，例如“请输入服务器名称”“IP 地址或域名格式不正确”“端口必须为 1–65535”。
- 允许同一地址建立多个不同名称或端口的条目，以支持不同用途和凭据覆盖。

## UI 和状态协调

新增 `NewServerRequest`，记录目标分组 ID、分组名称、预期资源库身份以及窗口宿主租约。它复用现有资源属性窗口协调器：

- 同一个请求只由一个有效窗口展示。
- 凭据窗口、删除确认和资源编辑窗口继续遵循现有的共享模态优先级。
- 宿主窗口关闭或租约失效时，请求被安全清理。
- 保存期间禁用重复提交；失败后保留用户输入并展示错误。

名称的自动填写仅在用户尚未主动修改名称时发生：输入地址后，名称同步为地址；用户编辑过名称后不再覆盖。

## 不同来源导入保护

同来源重新导入继续使用 `mergeReimport`，其中 `sourceFingerprint == nil` 的手动服务器和手动分组会保留原位置。

导入来源与当前资源库不同，且检测到手动项目时，先展示替换确认，至少说明手动服务器和手动分组数量。用户可以取消或明确继续替换。没有手动项目时沿用现有导入流程。

## 错误处理

- 所有配置写入继续走事务式仓库更新。
- 校验错误显示用户可理解的字段级信息。
- 目标分组消失、资源库在保存前被替换等竞争条件显示“资源库已发生变化，请重新添加”。
- 配置保存失败显示现有安全错误，不泄露文件路径、密码或底层实现细节。
- 创建成功前不改变当前选择；创建成功后才选择新服务器。

## 测试和验收

### 核心测试

- 名称、IPv4、IPv6、域名和端口的成功与失败边界。
- 在根分组和子分组创建服务器。
- 目标分组不存在时保持原快照不变。
- 新服务器获得 UUID，且来源指纹为 `nil`。
- 同来源重新导入保留手动服务器。

### 模型和持久化测试

- 无资源库时自动创建“我的服务器”并添加第一台服务器。
- 创建和配置保存为单次原子提交；失败时不留下空资源库。
- 已有资源库时添加到指定分组并自动选中。
- 重载持久化状态后服务器仍存在。
- 新服务器继续解析全局凭据，不创建明文密码数据。
- 资源库在保存期间改变时拒绝陈旧提交。
- 导入不同来源且存在手动项目时要求确认。

### UI 策略测试

- 顶部 `+` 菜单的项目、顺序和可用状态准确。
- 根分组和普通分组右键菜单均含 `添加服务器…`。
- 添加窗口的默认端口、自动名称、保存禁用状态和错误展示准确。
- 多窗口宿主租约不会产生重复窗口或跨窗口误关闭。

### 完成验证

- 执行项目全部自动测试。
- 构建发布版应用。
- 覆盖安装并打开新版，实际验证：无 `.rdg` 添加、已有 `.rdg` 根分组添加、子分组添加、重启恢复、全局凭据连接。

## 非目标

- 本次不在添加窗口内新增账号密码输入；服务器继续继承全局凭据，用户可在创建后使用现有服务器凭据覆盖功能。
- 本次不增加 `.rdg` 导出或改写功能。
- 本次不同时加载多个独立 `.rdg` 资源库。
