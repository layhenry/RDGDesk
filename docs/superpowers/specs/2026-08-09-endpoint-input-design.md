# RDGDesk 完整服务器地址输入设计

日期：2026-08-09
状态：已与用户确认，待实施

## 目标

让 RDGDesk 的“添加服务器”和“服务器属性”表单可以直接接受包含端口的完整服务器地址，例如 `q6id.cn:6609`，同时继续兼容现有的“主机地址 + 独立端口”输入方式。该升级只改善手动编辑体验，不改变 `.rdg` 导入、凭据继承、连接协议或持久化格式。

## 已确认的产品行为

### 支持的输入格式

地址栏支持以下形式：

- 域名或主机名：`q6id.cn`
- 域名或主机名加端口：`q6id.cn:6609`
- IPv4：`192.168.1.10`
- IPv4 加端口：`192.168.1.10:6609`
- 裸 IPv6：`2001:db8::10`
- 方括号 IPv6：`[2001:db8::10]`
- 方括号 IPv6 加端口：`[2001:db8::10]:6609`

IPv6 携带端口时必须使用方括号，从而避免把裸 IPv6 的最后一段误判为端口。

### 端口优先级

- 地址栏自带有效端口时，保存使用地址里的端口。
- 地址栏自带端口时，不改写独立的“端口”输入框；该输入框的当前内容也不参与保存校验。
- 地址栏不带端口时，保存使用独立“端口”输入框。
- 该规则同时适用于新增服务器和编辑服务器属性。

### 名称与持久化

- 新增表单在用户尚未手动编辑名称时，继续根据地址自动生成名称。
- 自动名称只使用解析后的主机，不包含方括号和端口。例如输入 `q6id.cn:6609` 时，默认名称为 `q6id.cn`。
- 最终仍生成现有的 `ServerPropertiesDraft`，其中 `host` 与 `port` 分开保存。
- 资源库序列化继续使用现有标准格式：域名和 IPv4 为 `host:port`，IPv6 为 `[host]:port`。

## 方案与架构

采用共享地址解析器，而不是在两个表单重复拆分逻辑，也不扩大 `RdcCore` 资源库编辑 API 的输入职责。

解析器位于 `RdcApp` 的资源库表单模型层，输入原始地址字符串与独立端口字符串，输出规范化的主机和最终端口，或返回可安全显示的校验错误。`NewServerEditorModel` 与 `ServerPropertyEditorModel` 共用该解析器，再把结果转换为现有 `ServerPropertiesDraft`。

数据流如下：

1. 用户编辑地址栏或独立端口栏。
2. 表单模型调用共享解析器。
3. 解析器识别地址是否携带端口并应用端口优先级。
4. 表单模型使用解析出的主机与端口调用现有 `ServerPropertiesDraft.validated()`。
5. 保存路径继续调用现有创建或更新 API，不改变资源库、配置仓库及连接引擎的边界。

这样可以让新增和属性编辑保持一致，同时把影响限制在手动输入层，不触碰 `.rdg` 解析和远程会话代码。

## 解析规则

解析前去除地址首尾空白。

### 方括号形式

- 以 `[` 开头的输入必须包含匹配的 `]`。
- 方括号内必须是合法 IPv6 地址。
- `]` 后只能为空，或为 `:<port>`。
- `]` 后为空时使用独立端口；存在端口时使用地址端口。

### 非方括号形式

- 合法的裸 IPv6 整体作为主机，不尝试从最后一个冒号拆分端口。
- 只有一个冒号时，将输入作为候选 `host:port` 解析；主机部分仍需通过现有 IPv4、DNS 或主机名校验。
- 没有冒号时，将整个输入作为主机并使用独立端口。
- 不能形成合法裸 IPv6、合法主机或合法完整地址的输入应被拒绝。

## 校验与错误处理

- 主机为空或格式错误时显示：`请输入有效的 IP 地址或主机名。`
- 地址中存在端口但不是 `1...65535` 的整数时显示：`地址中的端口必须是 1–65535 之间的整数。`
- 地址未携带端口时，独立端口不是 `1...65535` 的整数，继续显示：`端口必须是 1–65535 之间的整数。`
- 地址携带有效端口时，独立端口字段即使为空、非法或不同，也不阻止保存，因为它不会被使用。
- 格式错误不得产生部分草稿、配置写入或属性变更。
- 保存过程中现有的并发保护、回滚和安全错误提示保持不变。

## UI 行为

- 保留现有三个字段和整体布局，不增加新弹窗。
- 地址字段文案固定为 `IP 地址、域名或完整地址`。
- 不增加辅助说明，也不改变表单尺寸和主要操作路径。
- 独立端口框始终可见，并保持用户输入；地址自带端口时不自动覆盖它。
- 添加按钮与属性保存按钮根据解析后的最终草稿决定是否可用。

## 兼容范围

- 原有域名、IPv4、裸 IPv6 与独立端口输入继续工作。
- `.rdg` 导入不经过新解析器，行为不变。
- 已保存服务器的地址结构、搜索、证书信任、凭据继承和连接请求保持不变。
- 不自动创建或连接 `q6id.cn:6609`，避免在验收时改动用户资源库或发起未经确认的远程连接。

## 测试策略

所有实现遵循先失败测试、再最小实现、再通过测试的顺序。

### 解析器测试

- 域名与 IPv4 带端口可以拆分。
- 方括号 IPv6 带端口可以拆分。
- 域名、IPv4、裸 IPv6 与方括号 IPv6 不带端口时使用独立端口。
- 裸 IPv6 的最后一段不会被误判为端口。
- 地址端口覆盖独立端口，但不改写独立端口原始文本。
- 端口 `1` 和 `65535` 可用；`0`、`65536`、空值及非数字被拒绝。
- 缺失方括号、方括号后有多余字符、空主机和错误 IPv4 被拒绝。

### 表单模型测试

- 新增表单输入 `q6id.cn:6609` 后生成主机 `q6id.cn`、端口 `6609`，默认名称为 `q6id.cn`，独立端口文本保持原值。
- 属性表单输入完整地址后生成拆分后的草稿，并正确判断是否发生属性变化。
- 地址携带有效端口时，独立端口错误不阻止保存。
- 地址未携带端口时，继续执行原有独立端口校验。
- 保存失败仍显示现有安全消息且不产生配置副作用。

### 回归与交付验证

- 运行相关表单与资源库测试，确认新测试先因功能缺失而失败。
- 实现后运行完整测试套件和默认构建脚本。
- 生成并校验 `RDGDesk.app` 与 DMG。
- 覆盖安装后打开新增和属性表单，验证完整地址可通过校验；不保存真实测试服务器，不输入凭据，也不自动连接。

## 非目标

- 不改变 RDP 网络协议或 FreeRDP 连接参数。
- 不在本次工作中增加批量导入其他文件格式。
- 不把 URL、用户名、密码、路径或查询参数视为服务器地址。
- 不移除独立端口输入框。
